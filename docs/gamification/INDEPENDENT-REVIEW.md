## 最多五項具體阻擋與修法

### B1｜高優先・發布阻擋：共享裝置切換帳號洩漏未提交草稿

**位置：** `src/classroom-team-ui.js:5–6,12,15`；`classroom-cloud-ui.js` 的登出／使用者更換仍沿用同一 teamUI。

`drafts` 只以teamId索引，mount／登出不清除。A留下未提交理由，登出後B登入同隊，B的「我的理由」會帶出A草稿，且可用B身分送出。伺服器檢查uid不能消除這項前端誤歸屬。

本輪直接執行正式createTeamUI，最小host測試：mount A→oninput輸入私人草稿→mount(null,null)→切B→mount同隊，實際輸出：

```text
{"currentUser":"student-b","leakedDraft":true}
```

**修法：** 草稿按使用者／任務／隊伍隔離；登出與身分變更清空記憶體草稿、data、signature，遞增請求世代使在途回應失效。不要因修復而清除同一使用者一般重新整理時的草稿。

**必要證據：** A→登出→B同隊，以及A→B他隊的UI測試；延遲A請求在B登入後抵達不能渲染；B送出的內容不可包含A未提交文字。至少一次共享裝置實際登入切換驗證。

### B2｜中優先・發布阻擋：保存個人貢獻刪掉未送共同結論

**位置：** `src/classroom-team-ui.js:15` 的 `delete drafts[t.id]`。

同一隊的reason／reply／conclusion共用一個draft物件。先寫共同結論、再保存自己的新線索，成功後整個draft被刪，load重新渲染使共同結論消失，沒有提示。

本輪直接模組重現輸出：

```text
{ conclusionRetainedAfterSavingContribution: false }
```

**修法：** 成功送出貢獻只清對應欄位，保留conclusion；送出結論也只清成功提交的結論版本。若送出中使用者繼續輸入，不可清除更新後草稿。

**必要證據：** 寫結論→保存貢獻→結論完整保留；請求失敗仍保留；在途追加文字不被成功回應刪除。

### B3｜中優先・發布阻擋：重玩悄悄刪掉原有理由

**位置：** `src/adventure.js:18` 的 `.slice(-12)`；`adventure-ui.js` 宣稱再演練「保留原有歷程與收藏」。

第13次決策會遺失第1次理由。現有測試刻意斷言history.length=12，證明上限運作，卻沒有驗證使用者被告知或成果可保存。

本輪實跑13次決策：

```text
{ decisionsMade: 13, retained: 12, firstRetainedRound: 1 }
```

**修法：** 維持有界存檔，但不可默默丟資料。可採到上限先讓使用者匯出／封存，或達上限停止新增紀錄；若只保留最近12次，必須明示且提供保存舊理由的途徑，不能再承諾全部保留。不要無界放大存檔。

**必要證據：** 第12→13次、封存／匯出／存讀、收藏保留及失敗回復測試；UI文案和真正保存範圍一致。

### B4｜設計宣稱阻擋：資源與居民後果缺少可操作閉環

**位置：** `adventure.js:9,17–19`、`adventure-content.js` 的共同choices與成本、`adventure-ui.js` 的決策後區塊。

每篇訪查成本固定3，留下3時間與3援助；兩方案皆可行。決策後狀態只有choiceId／reason，剩餘資源無使用者操作，後果是一段固定文字。這支持「討論取捨」活動，不能支持契約中的「真取捨、可重配、可逆失誤修復」已完成，更不能以此給創意／稀缺／守護9分。

**修法：** 先選一篇做深：第一次安排後揭露有因果的新需要；剩餘資源影響兩種合理補救的可行性；允許重配或修正並保存前後理由及居民狀態。所有後果只在可恢復的演練內，原城與既有作品不扣減。擴十篇前先驗證一篇確實好玩。

**必要證據：** 同初始條件兩路徑形成不同後續可行集合；一次重配可真正恢復演練內需要；不可超支；保存／重玩後前後比較仍在。用學生口述判斷其是否理解誰受益、誰等待，而非只看餘額。

### B5｜設計宣稱阻擋：重玩沒有依證據產生的新發現

**位置：** `adventure.js:16` 的 `surprises[s.round%2]`，與 `adventure-content.js` 全篇相同成本骨架。

同篇同輪不論選哪條路徑都是同一問題；第3輪回到第1輪問題。角色尚無姓名與持續關係。十篇換文案能擴課文範圍，但不會自動形成深度探索或使命感。

**修法：** 以具姓名的改編角色串起前輪決策；新線索由前輪選擇或學生提出的待查問題觸發，讓第二輪需要重新解讀原文，而非只是再點另一按鈕。至少一條路徑要讓學生發現原先推論的界線。仍清楚標示教學改編、不虛構史實。

**必要證據：** 分支／重玩測試確認新線索與過去行動有因果；課堂觀察學生能提出新問題、引用證據修正原看法。沒有這類證據時，維持目前分數及「設計目標」說法。
