# 城市模擬第一輪評量

基準：`a6a7504`。開始時 `git status --short` 無輸出。只評量城市系統；未修改程式、未部署，亦不把新增需求宣稱為既有產品故障。

## 設計參照與範圍

以使用者指定的 SimCity 2000 城市經營循環作設計借鑑：配置資源、觀察供需、承受營運後果、調整投資。此處沒有主張逐項還原原作規格；不複製其圖像、聲音、程式或其他版權資產。汴水小鎮仍採原創宋代市井場景，水井、巡守、書院等是本專案的在地化設計。

## 模式相容契約

新增財政、需求、服務及人口限制只在 `management` 模式啟用；`sandbox` 保留自由建造及自動連路。真正的交易與尋路缺陷兩模式皆修正。既有存檔預設 sandbox；這是相容邊界，存檔遷移實作由其他領域負責。根代理已提供官方原手冊鏡像與 `REFERENCE.md`，本評量未自行逐頁核對原手冊，不主張逐項等同原作機制。

## 評分 rubric

所有維度使用同一套 0–5 分尺規：0＝程式無該因果機制；1＝只有狀態/外觀/文字；2＝單向可運作但玩家沒有完整取捨；3＝輸入、代價、結果閉環且有直接驗證；4＝處理容量、失效、恢復等邊界；5＝另有平衡情境和真人操作驗證。沒有真人驗證的本輪不能給 5。

| 維度 | 0–5 分 | 證據與判斷 |
|---|---:|---|
| 財政經營 | 0 | `Town.place`、`layRoad`、`upgradeBuilding` 無資金扣款；`createEconomy` 只追貨物。C01–C04、C11。 |
| 分區供需 | 0 | `Town.tick` 自動補滿住宅，無需求模型。C05–C07。 |
| 就業與消費 | 2 | 有職缺、實際到坊與購物貨物轉移，但工作依陣列、居民不消費。C08–C10、C16。 |
| 道路與物流 | 2 | BFS 尋路、貨物來源鏈可運作，但自動連接、固定物流且道路等級無效。C12–C15。 |
| 公共服務 | 1 | 書院、藥鋪、園景存在可觀察行程，無容量與城市服務效果。C17–C21。 |
| 環境與成長 | 1 | 外觀可升級，未將污染、園景、分級、民生形成因果。C22–C25。 |

**合計 6/30（20/100）**。這是相對「城市經營」新目標的成熟度評分，不是對既有市井觀察遊戲的整體品質評分。

## 具體問題清單與驗證

完整 25 項位於 `city.json`，ID C01–C25；22 項功能缺口、3 項行為缺陷（C08、C15、C16）。每項含檔案/符號證據、嚴重性、修法、驗收條件。

實際重現 C15：建立位於 (0,0) 的商鋪與一件布匹，將道路限制為城門單點 `33,-16`，訪客置於城門，呼叫 `tickLife(t,0.01)` 兩次。輸出顯示訪客仍在 `[33,-16]`、店門 `[0,2]`，卻 `sold.cloth=1`。這是可重現的狀態機故障，應優先修正。

其餘分數及差距依靜態原始碼評讀；沒有宣稱執行全套測試或瀏覽器驗收。

## 建議實作次序

1. 先修遠端交易與職缺可達性，再建立共用城市狀態、固定時間結算及單一數值表。
2. 財政、RCI、漸進人口、居民需求與真實路網一同形成最小經營循環。
3. 公共服務、污染、宜居與建物等級串入相同計算來源，避免各加一個互不影響的分數。
4. 以「均衡城／過度住宅／工坊密集／孤島街區／赤字恢復」五情境驗證，最後做實際 UI 驗收。
