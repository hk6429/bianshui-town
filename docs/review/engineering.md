# 工程可靠性評量 E01–E25

基準：`a6a7504`。範圍：存檔、模型邊界、可重現性、GPU生命週期、故障復原。只做評量，未修改遊戲原始碼。已先讀 `ux.json`，避開鍵盤、觸控及焦點項目；不評經濟設計與任務目標。

## 0–5 分規準

0＝未有可用能力；1＝核心流程存在但常見失敗無防護；2＝基本流程可用、資料邊界或故障復原不足；3＝主要失敗可處理且有聚焦測試；4＝有長時間、遷移與故障注入證據；5＝另具量化效能預算及持續回歸證據。這是專家工程評分，不是測試通過率。

| 面向 | 分數 | 主要理由 |
|---|---:|---|
| 存檔耐久與復原 | 1/5 | 單一key覆寫；壞檔會被新城取代；重置復原只在記憶體 |
| 資料驗證與完整性 | 1/5 | 頂層檢查存在，但方法、ID、座標、巢狀與配方邊界未守住 |
| 模擬一致性 | 2/5 | dt推進已有基本設計，但frame分割差異及讀檔重新導航改變狀態 |
| 編輯失敗保護 | 2/5 | 有單步快照復原；缺持久復原點及交易回滾 |
| GPU與長時間資源 | 2/5 | geometry有清理，專屬材質/紋理缺生命週期；重建範圍過大 |
| 安全與故障可見性 | 1/5 | 部分字串已有escape；數值/ID的HTML插值仍信任存檔；frame無錯誤邊界 |

## 限制與放行條件

- 本輪25項含已證實bug與標示gap的新可靠性契約，不能將gap當作已發生故障。
- 未跑瀏覽器、GPU壓力、WebGL內容遺失、跨分頁或真人測試；GPU問題來自建立/釋放對照，尚無記憶體曲線。
- 時間分割重現呈現差異，不宣稱所有業務結果皆不同；接受條件需先確定固定步長及背景政策。
- 存檔HTML風險目前入口是本機存檔；沒有證據支持遠端無互動攻擊。匯入功能若新增，必須共用驗證器。
- 工程項目具獨立接受條件，實作可共用同一schema、存檔服務或資源管理器；不得為每條重複造輪子。
- 全修放行需逐項提供來源diff及適合的聚焦測試；互動/硬體項目需瀏覽器證據。此評量本身不代表部署驗收。
