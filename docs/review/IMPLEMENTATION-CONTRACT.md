# 重整實作契約與工作包

此文件定義實作邊界，不代表任何待辦已完成。100 項逐項驗收仍以 ledger.json 為準。

## 玩家模式
- 新玩家開局預設呈現「城市經營」，也可明確選「自由營造」。經營介面不能藏在開發者選項。
- 舊存檔遷移保留自由營造，不自動對已建城市追扣資金；可從主選單切換並先顯示經營條件。
- 經營模式形成資金、供需、道路、服務、居民滿意與成長的完整閉環。真正故障在兩模式都修正。
- 遊戲化引導/挑戰是可開關偏好，不與是否財政經營混成一個欄位；文化閱讀隨時可用。

## 共用資料
- `town.city`：版本、模式、金庫、稅率、物流等級、遊戲日結算游標、帳本、分項民生與歷史數據。
- `town.journey`：版本、城市名稱、願景、引導、里程碑、委託、居民關係、主動讀訪、短箋、選集、書籤、探索及回顧。
- 交易與目標都從真實模擬狀態讀取；不得用純展示數字或測試專用分支假裝實作。
- 金錢用有界整數；規則表統一維護建設/升級費、營運費、等級容量、商品價值、服務容量與覆蓋。
- 各模組提供 pure query 讓預覽與提交共用規則；預覽不可扣費或增加目標進度。
- 玩家動作以明確事件記錄：inspect-person、read-work、build、upgrade、accept/decline-request 等。自動世界事件不冒充主動閱讀或觀察。
- 自訂文字只能 textContent 或統一 escape 輸出；名字不代替穩定 ID。

## 相依順序與有界工作包
1. **R：可靠性底座**。處理存檔白名單/驗證/恢復、交易與尋路正確性、時間與資料上限、資源生命週期；先修缺陷，不宣稱新經營循環完成。
2. **C-A：城市核心**。財政、RCI、人口與就業、成交稅基、玩家路網及物流；聚焦 C01–C16。
3. **C-B：公共服務與宜居**。水井、清運、巡守、醫療、教育、污染、公園、分級與滿意；C17–C25。
4. **O-A：目標與居民**。願景/引導/委託/里程碑/挑戰/居民關注/議事/回顧。
5. **O-B：文化與個人城市**。命名、書籤、讀訪、配對、短箋、策展、探索及事件補訪。
6. **U：城市操作介面**。共用驗證、鍵盤、觸控草稿、清單/圖層、焦點、可讀性與狀態。與各模組UI整合。
7. **V：獨立複評與發布**。每項對照正式實作與驗收、跨裝置/流程實測、再次四領域評分，完成100項才發布；正式逐檔雜湊回讀。

每工作包結束保存 handoff。下一包使用新工程代理，不讓同一代理跨多個里程碑長駐。共享 main.js 與 index.html 由根代理整合，其他代理只有明確授予時才能修改，避免互相覆寫。

## 放行證據
- 行為：固定情境、錯誤輸入、恢復、守恆、模式切換與冪等測試。
- 城市：均衡城、住宅過剩、工坊密集、孤立街區、赤字恢復至少五個可重播情境。
- 遊戲化：另一解法、拒絕/撤回重接、主動閱讀 vs 自動事件、重複動作不刷進度、可停止結語。
- UI：桌面、手機、短橫向、純鍵盤；必要項實際瀏覽器驗證，未測真人觸控/讀屏要明示。
- 每個 ledger ID 必須有直接覆蓋該 acceptance 的證據；單一總綠燈不得代替逐項審核。
